# Тренировки 2.0 — кандидат на предварительное тестирование (итерация 4)

**Статус:** исходники и автоматизированные проверки готовы. Публикация для основного iPhone **не разрешена**, пока не завершены проверки на реальном устройстве и переносе реальной базы 1.0. Рабочая ветка — `develop/v2`; `main` должна оставаться неизменной.

## Реализовано

- Пять вкладок («Сегодня», «Календарь», «Программы», «Прогресс», «Профиль») в тёмно-графитовой теме с красными акцентами.
- Календарь месяц/неделя; несколько активных программ и самостоятельные карточки занятий; разовые тренировки на любую дату; история и редактирование конкретной даты.
- Конечные многонедельные программы и повторяющаяся неделя, пошаговый конструктор. Изменения сначала остаются в **черновике**, а по «Сохранить» применяются к **этой неделе / выбранным неделям / всем будущим неделям**. Версии расписания и исключения по датам сохраняют уже прошедший план, начатые и законченные занятия.
- Копирование недель, архивирование и возобновление программ с сохранением дней недели. Удаление программы с историей запрещено. При совпадении программ отображается ненавязчивое предупреждение.
- Банк упражнений: одна основная категория, мышцы, оборудование, место, уровень, источник, поиск, избранное, альтернативы, центральные редактируемые справочники, архивирование/восстановление. Использованное упражнение нельзя уничтожить вместе с историей.
- Журнал выполнения: плановые подходы не считаются выполненными без галочки; фактические повторения/вес корректируются; оценки «до» и «после» обязательны для обычной тренировки и выбираются явно ползунками 0–10. Задним числом оценки необязательны (отсутствие данных ≠ ноль). Незавершённая тренировка сохраняется в статусе «В процессе».
- Отдельные формы для силовых (подходы/вес/повторы), кардио/тенниса (длительность, при необходимости дистанция), йоги/мобильности/разминки (отметки упражнений и длительность). Таймер отдыха и автопрогрессия не добавлялись.
- Прогресс: повторные взвешивания в день, расширенные и пользовательские замеры, сравнение дат, история, цели. Графики веса, объёма нагрузки и повторений; оценки боли до/после по одной зоне; недельные и месячные отчёты с фильтрами и сопоставлением эквивалентных периодов.
- Профиль: редактирование целей с историей целевых значений, настройка порядка/активности болевых зон, личные данные, ручной замок, смена пароля, резервные копии и напоминания через семь дней.
- AES-GCM/PBKDF2 для локальных данных; раздельное шифрованное хранилище 2.0; экспорт и восстановление с обязательным подтверждением внешней страховочной копии. При записи localStorage с ошибкой предыдущее сохранённое состояние не заменяется в памяти.
- Перенос данных 1.0 с сохранением оригинального зашифрованного хранилища. Импортированные отметки, веса и заметки видны в **отдельном неизменяемом историческом режиме** без приписывания неизвестных фактических повторений или оценок до/после.
- PWA manifest и service worker, кэширование оболочки и обновления без принудительной перезагрузки активной тренировки.
- **Новый сценарий:** перенос из локально выбранного зашифрованного файла 1.0 при первом запуске на отдельном HTTPS-адресе. Не удаляет исходный файл, не передаёт его на сервер и не заменяет имеющуюся базу 2.0. При ошибке пароля/формата новое хранилище не создаётся.
- PNG-иконки 180/192/512 для домашнего экрана iPhone и PWA; обновлён офлайн-кэш.

## Автоматические проверки

В каталоге `v2`:

```bash
node tests/core.test.mjs
node tests/analytics.test.mjs
node tests/schedule_versions.test.mjs
node tests/storage_atomicity.test.mjs
python tests/browser_smoke.py
python tests/editor_flow.py
python tests/v1_backup_import_ui.py
node tests/v1_backup_crypto.test.mjs
```

Эти проверки пройдены в окружении разработки 09.11.2026. Node использует настоящую реализацию WebCrypto, а браузерные smoke-тесты запускаются из `about:blank` и **подменяют криптографию и localStorage исключительно для теста интерфейса**.

`python tests/real_crypto_pwa.py` — попытка реального браузерного запуска с localhost. В текущем окружении Chromium возвращает `ERR_BLOCKED_BY_ADMINISTRATOR` при переходе на локальный HTTP-адрес. Этот тест **НЕ пройден** и остаётся обязательным на доступной тестовой машине или устройстве.

## Тестовая HTTPS-публикация

GitHub Pages текущего репозитория уже обслуживает основную версию 1.0. Размещение сборки 2.0 в том же Pages без отдельной среды может затронуть основной сайт или его браузерное хранилище. **Не менять настройки Pages основного репозитория.** Подготовлен пакет для нового тестового репозитория и отдельного HTTPS-origin (см. `DEPLOY_TEST_SITE.md`). На тестовом origin невозможно автоматически прочесть `localStorage` версии 1.0: нужно импортировать **копию зашифрованного экспорта** через кнопку на первом экране.

## Обязательные проверки перед релизом

1. Safari iPhone и установленная PWA: шифрование WebCrypto, повторный вход после полной перезагрузки, работа без интернета после первого открытия.
2. Работа через несколько часов в фоне без таймерной блокировки (после фактического уничтожения процесса пароль допустимо запросить снова).
3. Создание и редактирование программы, применение изменений только к выбранным датам, архивирование и возобновление; проверка прошлой истории.
4. Полная миграция на **копии** настоящего архива 1.0 (включая сопоставление числа дат/отметок/весов/заметок и поведение при несовпадении хранилищ Safari/PWA).
5. Восстановление из файла с правильным и неверным паролем, внешняя страховочная копия, ошибки quota и повреждённого файла.
6. Публикация новой версии кода и обновление PWA без потери данных, без перерыва активной тренировки.
7. Навигация, клавиатура и длинные формы на фактическом iPhone, в том числе при заполнении ползунков и подходов.

**Не вставлять единственный экземпляр ценных данных в тестовую сборку.** Резервная копия 1.0 должна оставаться сохранённой отдельно в приложении «Файлы». Данные Safari и установленного PWA могут находиться в разных контейнерах; автоматический перенос между ними не гарантирован.

## Локальный запуск

Для тестирования на компьютере (не `file://`):

```bash
python -m http.server 8000
```

Открыть `http://localhost:8000/`. Для проверки на iPhone нужен доступный HTTPS-адрес тестовой установки. Публиковать `main` до выполнения обязательных проверок нельзя.
