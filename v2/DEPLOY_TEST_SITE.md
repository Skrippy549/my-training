# Публикация тестовой версии 2.0 без изменения 1.0

Пакет `Trenirovki_2_0_https_preview_site.zip` содержит **только публичные файлы приложения**, никакие личные измерения, журналы или пароли в него не включаются.

1. На GitHub создать **новый публичный репозиторий**, например `my-training-v2-preview`. Не изменять репозиторий `my-training` и его настройки Pages.
2. Распаковать архив тестового сайта и загрузить **содержимое** в корень нового репозитория (GitHub → Add file → Upload files → Commit changes).
3. В новом репозитории открыть Settings → Pages → Build and deployment → Deploy from a branch → `main`, `/ (root)` → Save.
4. После того как GitHub покажет адрес опубликованного тестового сайта, открыть его в Safari на iPhone. Проверить создание новой тестовой базы; не вводить реальные данные, пока не проверены безопасность, офлайн и экспорт.
5. Для отдельной проверки переноса: в рабочей версии 1.0 создать зашифрованную копию, сохранить **копию файла** в «Файлы» и выбрать на первом экране тестовой версии «Перенести из зашифрованной копии 1.0». Используется прежний пароль. Тестовая база находится на **другом HTTPS-адресе**. Исходные файлы и база 1.0 не изменяются.
6. Проверить вход после перезагрузки, работу без сети, запись тренировки, перезапуск, экспорт и восстановление. Следовать `IPHONE_QA.md`. Отдельно проверить установленную PWA: её хранилище может отличаться от Safari.

**Не публиковать сборку в `main` рабочего репозитория и не заменять приложение 1.0 до принятия результатов теста.**

## Ограничения

Это инструкция, а не подтверждение, что HTTPS-сайт уже создан. Создание нового репозитория и включение Pages выполняется владельцем GitHub, если текущая интеграция не предоставляет управление этими настройками. Из соображений безопасности не рекомендовано вводить пароль от реальной базы в онлайн-превью на стороннем домене; только на контролируемом GitHub Pages origin.
